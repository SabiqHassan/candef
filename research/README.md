# research/: the real CANDEF corpus

This folder holds **real data only**. Synthetic data is generated by `pipeline/demo` and never lives here; the research build refuses fixture data (`pipeline/research/gates.ts`).

**Nothing here is published until the owner approves it.** The compiler publishes only records that are `verified` and carry a review whose hash still matches their content. Everything an agent writes is `verification: proposed`.

## Layout

```
research/
  taxonomy.yaml          TaxonomyNode[]  (owner-approved 2026-10-13, P-24: 10 sectors, 30 subsectors; IDs are permanent)
  programs.yaml          Program[]       (funding programs: { id, funderId, name })
  sources/<id>.yaml      one Source per file; id defaults to the file name
  orgs/<slug>.yaml       one organization per file: company, investor, fund, government body…
```

Files whose names start with `_` are ignored, so they can hold notes.

**Never commit captured page text or excerpts here** (D-15). Captures live in the gitignored `research-cache/`.

## Organization file

```yaml
org: { id: org_<ULID>, kind: company, slug: example-co, name: Example Co }
defaults: { createdBy: "agent:claude-code" } # verification defaults to proposed
facts:
  - predicate: legal_name
    value: Example Co Inc.
    src: ["src_example_release#para 2"] # "sourceId#locator"; a locator is required
  - predicate: registry_id
    value: { system: cra-bn, value: "123456789" }
    src: ["src_corporations_canada#corporation 1234567"]
rounds:
  - id: fin_example_seed # explicit IDs for rounds, agreements and acquisitions
    eventState: announced
    roundLabelAsStated: Seed
    stage: seed
    instrument: equity
    proceeds: primary
    participantsCompleteness: partial_named
    src: ["src_example_release#para 1"] # inherited by disclosures and participations (never the review)
    disclosures:
      - {
          date: "2024-03",
          kind: single,
          amountBasis: cumulative_round_total,
          amount:
            { amount: "2500000", currency: CAD, disclosure: disclosed, asStated: "$2.5 million" },
        }
    participations:
      - { reportedName: Example Ventures, investorId: org_<ULID>, role: lead }
agreements: [] # canonical Agreement records (usually from the government import, after review)
acquisitions: []
research: # the research ledger: what was searched, when, with what outcome
  - {
      topic: financing,
      sourcesSearched: [company site, BetaKit],
      outcome: found,
      by: "agent:claude-code",
      at: "2026-10-13",
      nextReview: "2027-04",
    }
```

Every field follows the canonical schema in `src/domain/schema/corpus.ts`. The loader (`pipeline/research/load.ts`) expands this compact form and reports problems as `file:path: message`.

## Workflow (`npm run candef -- <command>`)

Set `CANDEF_AUTHOR` (or pass `--by`) so every record says who wrote it.

1. **Create the entity.** `new company "Example Co"` mints an ID and a skeleton. It refuses a name that normalizes to an existing organization of the same kind. If two look alike but differ, record `distinctFrom: [org_…]` on one of them.
2. **Register each source you read.** `source add <url> --kind company_release --tier T2 --publisher … --title …`. The ID is derived from the canonical URL, so a page can't be added twice. Permissions start as `unknown` (= denied).
3. **Optionally capture the page.** First read the site's terms, record them as `permissions.capture: allowed` with a `basis`, then run `capture <sourceId>`. It checks robots.txt and stores the bytes in `research-cache/` (never Git).
4. **Write facts, rounds and agreements** in `orgs/<slug>.yaml`, with `src: ["sourceId#locator"]`.
5. **Record what you searched,** found or not: `ledger <slug> financing none_found --searched "company site; BetaKit" --next 2027-04`. Without a ledger entry a topic shows as "not yet researched"; with `none_found` it shows as "not found in reviewed sources".
6. **Check:** `validate`. It shows load errors, gates (duplicates, dangling IDs, fixture data) and data-quality flags. It publishes nothing.
7. **Hand over:** `report` writes the semantic review report (HTML, `research-cache/reports/`).
8. **Owner only:** `review --org <slug>` (or `review <id…>`) in the owner's own terminal. It approves only records that pass their evidence rule. Agents never run it.

### Government disclosures (TBS contracts, grants and contributions)

1. **Register identifiers** as facts:
   - a company's business number: `registry_id { system: cra-bn, value: "123456789" }`;
   - a postal code inside `hq_location` (`postalCode`);
   - a department's TBS code on its government-body org: `registry_id { system: tbs-owner-org, value: dnd-mdn }`.
2. **Register the dataset** as a source: `source add <dataset url> --kind gov_dataset --tier T1 …`.
3. **Build the index:** `gov-index` writes `entities.json` and `bodies.json` to `research-cache/imports/`.
4. **Run the importer:** `npx tsx pipeline/ingest/gov/cli.ts --out research-cache/imports/<date> --index … --bodies …`, plus any of `--contracts <csv> --contracts-source <id>`, `--grants <csv> --grants-source <id>` and `--canadabuys <csv> --canadabuys-source <id>` (CanadaBuys contract history; contact columns are never read). Read `match-report.md`: ambiguous rows are never imported automatically.
5. **Accept proposals:** `gov-accept <out>/proposed-agreements.json <agreementId…>` adds the chosen proposals, still `proposed`.

### Duplicates and merges

- **`validate` fails on likely duplicates:** the same registry ID, or the same normalized name and kind.
- **If they are different entities,** add `distinctFrom: [org_…]` to one organization.
- **If they are the same entity,**
  - set `mergedInto: <surviving org id>` on the duplicate;
  - then **move** every fact, round, agreement and ledger entry to the surviving organization's file; the `merged-reference` gate lists them;
  - moved records need review again, because approvals are tied to their exact content.
- **The duplicate's old address redirects** to the surviving dossier.

### Backing up the research cache (D-15, P-30: Google Drive)

`research-cache/` is not in Git and parts of it (captures) can't be recreated. Back it up **encrypted** to a folder that Google Drive for desktop syncs. No Drive API, account token or credential is used by CANDEF: the tool writes to a local folder and Google's own app syncs it.

**One-time setup (owner):**

1. Google Drive for desktop: installed and signed in (2026-10-13). It mounts `G:\My Drive`, and the folder `G:\My Drive\CANDEF-backup` exists. Check in drive.google.com that it is **not shared**.
2. Choose a passphrase of 16+ characters and keep it in your password manager. **Without it the backup cannot be restored.** It is never stored by CANDEF or written to the backup.

**Each backup** (PowerShell; the passphrase lives only in that terminal session):

```
$s = Read-Host "CANDEF backup passphrase" -AsSecureString
$env:CANDEF_BACKUP_PASSPHRASE = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
npm run candef -- backup --to "G:/My Drive/CANDEF-backup" --encrypt --exclude gov-data/
npm run candef -- backup-verify --from "G:/My Drive/CANDEF-backup"
Remove-Item Env:CANDEF_BACKUP_PASSPHRASE
```

`Read-Host -AsSecureString` keeps the passphrase off the screen and out of the command history. Never type it into a chat with an AI agent, a file or a commit.

- Every file is encrypted (AES-256-GCM, key from the passphrase via scrypt), checked by decrypting it back, and listed in `manifest.json` with its SHA-256. File **names** stay readable in the manifest; contents do not.
- Unchanged files are skipped. A changed file keeps its previous encrypted copy as `<name>.enc.prev-<hash>`; nothing is silently overwritten.
- `--exclude gov-data/` skips the multi-GB open-government downloads, which can be downloaded again (their SHA-256 is in `research-cache/gov-data/<date>/SHA256SUMS`).

**Restore test** (do it once after setup, then every few months): `npm run candef -- restore --from "G:/My Drive/CANDEF-backup" --to "C:/Users/<you>/candef-restore-test"` (an empty or new folder), then compare with `research-cache/`. A backup that has never been restored is not yet trusted.

Licensing: captures are only taken where a source's permissions allow it (`permissions.capture`), and a private encrypted backup is retention, not redistribution.

## Builds

- `npm run data:research`: validates, compiles and writes `public/data/research/` plus `metrics.json` (the D-03 trigger metrics).
- `npm run build:research`: a production build of the app on the research dataset only (no demo data).

## Rules that the tooling enforces

- Money is a decimal **string**, or `null` when a disclosure doesn't state it (never `""`, never 0). Currency is explicit, or `unknown`; it is never defaulted to CAD.
- Grants and procurement are separate agreement families. A grant never implies a customer.
- Search-engine snippets are discovery, never evidence. Cite only pages actually read.
- Person data: professional role facts only (D-17).
